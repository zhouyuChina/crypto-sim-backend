# 生产环境数据库迁移指南 - 消息已读功能

> **警告**：在执行任何生产环境操作前，务必先备份数据库！

---

## 📋 迁移概述

### 本次迁移内容

为 `ChatMessage` 表添加消息已读功能的字段：

- `isRead` (Boolean) - 消息是否已读，默认 `false`
- `readAt` (DateTime, nullable) - 消息已读时间

为 `ChatConversation` 表添加未读计数字段：

- `unreadUserCount` (Int) - 用户未读消息数，默认 `0`
- `unreadAdminCount` (Int) - 管理员未读消息数，默认 `0`

### 影响评估

- ✅ **向后兼容**：新增字段都有默认值，不影响现有数据
- ✅ **零停机**：可以在不停机的情况下执行
- ✅ **性能影响**：添加了 `isRead` 索引，可能会短暂锁表（通常 < 1 秒）
- ⚠️ **数据迁移**：现有消息将被标记为未读（符合预期）

## 📝 生成迁移文件

### 步骤 1: 检查 Schema 差异

```bash
# 连接开发数据库，检查是否有未提交的 schema 变更
npx prisma migrate status

# 输出应显示: "Database schema is up to date!"
```

### 步骤 2: 生成新迁移（如果需要）

**重要**：如果本地数据库已经有 `isRead` 和 `readAt` 字段，但没有对应的迁移文件：

```bash
# 创建迁移文件
npx prisma migrate dev --name add_message_read_status --create-only

# 这将生成迁移文件但不会立即应用
```

**手动创建迁移文件**（如果自动生成有问题）：

```bash
# 创建迁移目录
mkdir -p prisma/migrations/$(date +%Y%m%d%H%M%S)_add_message_read_status

# 创建迁移 SQL 文件
cat > prisma/migrations/$(date +%Y%m%d%H%M%S)_add_message_read_status/migration.sql << 'EOF'
-- AddMessageReadStatus Migration

-- Step 1: 为 ChatMessage 表添加已读字段
ALTER TABLE "ChatMessage"
  ADD COLUMN IF NOT EXISTS "isRead" BOOLEAN NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS "readAt" TIMESTAMP(3);

-- Step 2: 为 ChatConversation 表添加未读计数字段
ALTER TABLE "ChatConversation"
  ADD COLUMN IF NOT EXISTS "unreadUserCount" INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS "unreadAdminCount" INTEGER NOT NULL DEFAULT 0;

-- Step 3: 为 isRead 字段创建索引（提升查询性能）
CREATE INDEX IF NOT EXISTS "ChatMessage_isRead_idx" ON "ChatMessage"("isRead");

-- Step 4: 为现有对话计算未读消息数（可选，如果有历史数据）
-- 注意：这可能需要一些时间，取决于数据量
UPDATE "ChatConversation" AS c
SET
  "unreadUserCount" = (
    SELECT COUNT(*)
    FROM "ChatMessage" m
    WHERE m."conversationId" = c.id
      AND m."senderType" = 'ADMIN'
      AND m."isRead" = false
  ),
  "unreadAdminCount" = (
    SELECT COUNT(*)
    FROM "ChatMessage" m
    WHERE m."conversationId" = c.id
      AND m."senderType" = 'USER'
      AND m."isRead" = false
  );
EOF
```

### 步骤 3: 验证迁移文件

```bash
# 查看生成的迁移文件
cat prisma/migrations/*/migration.sql

# 确认 SQL 语句正确
```

## 🚀 执行生产环境迁移

### 方法 1: 使用 Prisma Migrate（推荐）

```bash
# 1. 设置生产环境变量
export DATABASE_URL="postgresql://username:password@production-host:5432/crypto_sim"

# 或者使用 .env.production
cp .env.production .env

# 2. 部署迁移到生产环境
npx prisma migrate deploy

# 输出应显示:
# "1 migration found in prisma/migrations"
# "The following migration have been applied:"
# "  └─ 20XXXXXX_add_message_read_status"
```

### 方法 2: 手动执行 SQL（更安全）

如果您希望更精细地控制迁移过程：

```bash
# 1. 连接到生产数据库
PGPASSWORD=your_password psql \
  -h production-host \
  -U username \
  -d crypto_sim

# 2. 在 psql 中执行以下操作：

-- 开始事务
BEGIN;

-- 检查表是否存在
SELECT COUNT(*) FROM "ChatMessage" LIMIT 1;
SELECT COUNT(*) FROM "ChatConversation" LIMIT 1;

-- 执行迁移 SQL（粘贴上面生成的迁移文件内容）
ALTER TABLE "ChatMessage"
  ADD COLUMN IF NOT EXISTS "isRead" BOOLEAN NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS "readAt" TIMESTAMP(3);

ALTER TABLE "ChatConversation"
  ADD COLUMN IF NOT EXISTS "unreadUserCount" INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN IF NOT EXISTS "unreadAdminCount" INTEGER NOT NULL DEFAULT 0;

CREATE INDEX IF NOT EXISTS "ChatMessage_isRead_idx" ON "ChatMessage"("isRead");

-- 验证字段已添加
\d "ChatMessage"
\d "ChatConversation"

-- 如果一切正常，提交事务
COMMIT;

-- 如果有问题，回滚事务
-- ROLLBACK;

# 3. 退出 psql
\q

# 4. 标记迁移为已应用（告诉 Prisma 已经应用了）
npx prisma migrate resolve --applied 20XXXXXX_add_message_read_status
```

## 🔄 回滚计划

如果迁移后出现问题，可以使用以下方法回滚：

### 快速回滚（删除字段）

```sql
BEGIN;

-- 删除添加的字段
ALTER TABLE "ChatMessage"
  DROP COLUMN IF EXISTS "isRead",
  DROP COLUMN IF EXISTS "readAt";

ALTER TABLE "ChatConversation"
  DROP COLUMN IF EXISTS "unreadUserCount",
  DROP COLUMN IF EXISTS "unreadAdminCount";

-- 删除索引
DROP INDEX IF EXISTS "ChatMessage_isRead_idx";

COMMIT;
```

### 完整回滚（恢复备份）

```bash
# 1. 停止应用服务（可选，但推荐）
# systemctl stop your-app-service

# 2. 恢复数据库备份

  -h production-host \
  -U username \
  -d crypto_sim \
  -c \
  crypto_sim_backup_YYYYMMDD_HHMMSS.dump

# 3. 重启应用服务
# systemctl start your-app-service
```

## 📊 性能优化建议

### 1. 索引优化

迁移已经创建了 `isRead` 索引，如果有大量未读消息查询，可以考虑添加复合索引：

```sql
-- 为常见查询场景创建复合索引
CREATE INDEX IF NOT EXISTS "ChatMessage_conversation_sender_read_idx"
ON "ChatMessage"("conversationId", "senderType", "isRead");
```

### 2. 分批更新（大数据量场景）

如果有大量历史对话需要计算未读数，建议分批更新：

```sql
-- 分批更新，每次处理 1000 条
DO $$
DECLARE
  batch_size INT := 1000;
  offset_val INT := 0;
BEGIN
  LOOP
    UPDATE "ChatConversation" AS c
    SET
      "unreadUserCount" = (
        SELECT COUNT(*)
        FROM "ChatMessage" m
        WHERE m."conversationId" = c.id
          AND m."senderType" = 'ADMIN'
          AND m."isRead" = false
      ),
      "unreadAdminCount" = (
        SELECT COUNT(*)
        FROM "ChatMessage" m
        WHERE m."conversationId" = c.id
          AND m."senderType" = 'USER'
          AND m."isRead" = false
      )
    WHERE c.id IN (
      SELECT id FROM "ChatConversation"
      ORDER BY id
      LIMIT batch_size OFFSET offset_val
    );

    EXIT WHEN NOT FOUND;
    offset_val := offset_val + batch_size;

    -- 短暂延迟，避免数据库压力过大
    PERFORM pg_sleep(0.1);
  END LOOP;
END $$;
```

## 🆘 故障排查

### 问题 1: 迁移失败，提示字段已存在

**原因**：字段可能已经手动添加过

**解决**：
```sql
-- 检查字段是否存在
SELECT column_name, data_type, column_default
FROM information_schema.columns
WHERE table_name = 'ChatMessage'
  AND column_name IN ('isRead', 'readAt');

-- 如果字段已存在，标记迁移为已应用
npx prisma migrate resolve --applied migration_name
```

### 问题 2: 索引创建缓慢

**原因**：数据量大，创建索引需要时间

**解决**：
```sql
-- 使用 CONCURRENTLY 选项创建索引（不阻塞写入）
CREATE INDEX CONCURRENTLY IF NOT EXISTS "ChatMessage_isRead_idx"
ON "ChatMessage"("isRead");
```

### 问题 3: 未读计数不准确

**原因**：迁移时未正确计算历史数据

**解决**：
```sql
-- 重新计算所有对话的未读数
UPDATE "ChatConversation" AS c
SET
  "unreadUserCount" = (
    SELECT COALESCE(COUNT(*), 0)
    FROM "ChatMessage" m
    WHERE m."conversationId" = c.id
      AND m."senderType" = 'ADMIN'
      AND m."isRead" = false
  ),
  "unreadAdminCount" = (
    SELECT COALESCE(COUNT(*), 0)
    FROM "ChatMessage" m
    WHERE m."conversationId" = c.id
      AND m."senderType" = 'USER'
      AND m."isRead" = false
  );
```
